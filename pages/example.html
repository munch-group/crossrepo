Reading another project’s results

labdata lets one project read result files produced by another, without submodules, without cloning, and without downloading anything by hand.

A repository publishes by committing a labdata.yml in the results/ directory at its root, naming the files it wants others to see and saying what each one holds. Everything else in results/ stays private to that project.

This page builds a small repository so that it runs anywhere, then uses the python API on it. Reading repositories on GitHub works exactly the same way and is shown at the end.

import pandas as pd
import vscodenb
import labdata

What gets published

results/labdata.yml is the whole of it. Keys are file names, paths, or globs; values say what the file holds. You can list parquet folders as if they were files, since they load as such.

files:
    output.csv: Some csv file
    large_data.parquet: large data set 
    
labdata.refresh()

What is published

labdata.list() is the python side of labdata list. Point it at the directories your clones live in, or at GitHub — here we pass the settings directly so this page does not touch your own configuration.

labdata.list()

scratch_notes.csv is committed but absent: it is not named in the manifest. by_chrom is one row rather than three, because the manifest names the directory — parts says how many files are behind it.

The version is left out by default, since it is a full commit sha and every file a repository publishes carries the same one. Ask for it when you want it:

labdata.list(version=True)[['name', 'description', 'version']]

Notice what it printed. Without a version it takes the current one and tells you the sha that pins it, together with the call that does so — paste that back into the cell and the notebook reads the same bytes next year.

A pinned call is silent, and the sha is a full one, so it also means something to git show or a GitHub URL without labdata in hand.

version = labdata.list(version=True)["version"].iloc[0]

df = pd.read_csv(labdata.get("x-gwas", "hits.csv", version))
df.shape
(3, 3)

A dataset split over many files

A table too large for one file — a .parquet directory partitioned to stay under GitHub’s file size limit — is published by naming the directory. get then returns the directory, with every part in it.

directory = labdata.get("x-gwas", "by_chrom")

print(directory.is_dir())
sorted(p.name for p in directory.iterdir())

For a real partitioned parquet table the last step is simply

pd.read_parquet(labdata.get("x-gwas", "variants.parquet"))

since read_parquet takes a directory. Nothing about .parquet is special to labdata — naming a directory in the manifest is what makes it a dataset, so .zarr and anything else shaped that way work the same.

History

The catalog stamps every file with the repository’s current commit. labdata.versions() shows the commits in which the file itself changed, which is the useful set to pin.

labdata.versions("x-gwas", "hits.csv")
version date bytes parts tags subject
0 2c7b5f1b7395bcea03cac7c13687820afb3f03cf 2026-08-31 61 0 publish association results

When nothing shows up

An empty catalog has several ordinary causes and they look alike from outside. labdata.diagnose() says which it is, reading only local git.

print("\n".join(labdata.diagnose(Config(roots=["~/no-such-place"]))))
  ~/no-such-place: no such directory
  github: no owners or repos configured, so nothing is read from GitHub

Reading GitHub, without cloning

Everything above works the same against repositories on GitHub, which are read over the API — nothing is cloned, and the repositories need not be checked out at all. Name the organisations, or single repositories, in ~/.config/labdata/config.toml:

owners = ["munch-group", "kaspermunch"]
repos  = ["someone-else/shared-results"]   # optional extras

Then the calls need no cfg= at all:

labdata.list()
labdata.list(url=True)                     # with the URL of each version

df = pd.read_csv(labdata.get("x-gwas", "hits.csv"))

Authentication is GITHUB_TOKEN, or whatever gh auth login already stored. Cataloguing costs three or four requests per repository and is flat in the number of files, and a repository with no labdata.yml costs a single request.

URLs name the commit rather than a branch, so they keep pointing at the bytes that were cataloged:

https://raw.githubusercontent.com/munch-group/x-gwas/770170789d73.../results/hits.csv

Content is cached under its git blob sha, so a file you already have is never downloaded twice, whichever way it first arrived.

import shutil

shutil.rmtree(workspace)          # tidy up after the page
